# adviser — 실행은 Kiro, 판단이 어려울 때만 Fable에게 묻는다

진짜 advisor tool(API 서버 도구)은 실행자의 전체 대화를 자동으로 넘겨받지만, Kiro 안에서는 그게 불가능하다. 그래서 **질문에 맥락을 직접 적어야 한다**(아래 형식).

자문역은 **읽기 전용**이다. 코드를 직접 읽고 답하지만 파일을 고치지 않는다. 고치는 것은 항상 너(Kiro)다.

## 언제 부르나 (Anthropic advisor tool 권장 타이밍을 그대로 따른다)
- **본격 작업 전에 1번**: 파일 찾기·읽기 같은 방향 잡기를 먼저 하고, 쓰기·수정·해석 확정 **전에** 부른다. 조언의 가치는 접근이 굳기 전 첫 호출에서 가장 크다.
- **끝났다고 말하기 전에 1번**: 부르기 전에 결과물을 먼저 저장한다(파일 쓰기·커밋). 호출에 시간이 걸린다.
- **막혔을 때**: 같은 오류 반복, 접근이 수렴하지 않음, 결과가 안 맞음. **접근을 바꾸려 할 때**도.
- 작업 하나에 2~3회. 방금 읽은 도구 출력이 다음 행동을 정해 주는 짧은 단계에서는 부르지 않는다.
- 할 일 목록·스펙 문서를 쓰기 **전에** 부른다. 조언이 그 계획으로 흘러 들어가게.

## 조언을 다루는 법
조언에 무게를 둔다. 따랐는데 실제로 실패했거나 1차 근거(파일 내용, 오류 원문)가 조언과 다르면 그때 조정한다.
내 테스트가 통과했다는 것은 조언이 틀렸다는 증거가 아니다.

## 어떻게 부르나
프로젝트 루트에서 셸로 실행한다. 한 번에 1~3분 걸린다.

```bash
~/.kiro/skills/adviser/ask.sh "질문"
ADVISER_FILES="hooks/write_page_guard.py PLAN.md" ~/.kiro/skills/adviser/ask.sh "질문"
```

## 질문은 이렇게 쓴다 (자문역은 이 대화를 못 본다)
1. 하려던 것 한 줄
2. 지금 상태: 실패한 명령과 오류 원문, 또는 갈리는 선택지 A/B
3. 이미 해 본 것
4. 알고 싶은 것 하나

나쁜 질문: "왜 안 돼?" / 좋은 질문: "write_page_guard.py의 source_exists()를 segments.json 기준으로 바꿨는데
`[[L3#s7@t=340]]`가 거부된다. segments.json에는 s=7, 312~340.4가 있다. 비교식이 문제인지 s 타입이 문제인지."

## 답을 받은 뒤
- 답의 "다음 단계"를 그대로 실행한다. 답과 다르게 가려면 이유를 사용자에게 한 줄로 말한다.
- 자문 기록은 `.adviser/log.md`에 쌓인다. 같은 질문을 다시 하기 전에 먼저 읽는다.
- 호출이 실패하면(로그인 만료 등) 재시도하지 말고 사용자에게 알린다.
