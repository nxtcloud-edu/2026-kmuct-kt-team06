## 0. 한 줄

**강의 영상·전사본·슬라이드를 넣으면, 모든 문장에 "몇 강 몇 초"가 붙은 위키가 쌓인다.** 문장을 누르면 그 장면으로 점프하고, 영상은 구간 끝에서 멈춰 그 자리에서 필기를 받는다.

## 1. 문제 정의 (심사 ① — 수치로)

✅ **설문 「강의 녹음·AI 요약 이용 조사」 N=96** (2학년 52 · 4학년 15 · 1학년 14 · 3학년 12 · 기타 3, 국민대 SW·AI학부 외 타교 포함). 원본 `강의 녹음·AI 요약 이용 조사(응답).xlsx`.

| # | 발표에 쓸 숫자 | 근거 |
|---|---|---|
| **1** | **요약 AI를 써 본 학생 75명 중 64명(85%)이 요약을 읽고도 원본으로 되돌아갔다** | 전체 96명 기준 67% |
| 2 | 되돌아간 이유(복수, 64명): 시험에 나올 문장·표현 확인 **59%** · 원본을 봐야 이해됨 **53%** · **AI 요약이 틀린 것 같아서 52%** · 위치(몇 주차·몇 분) 필요 17% | 기타 서술: "원본이랑 교차검증", "내용 빼먹어서", "정확한 용어 확인" |
| 3 | 강의 자료를 요약 AI에 넣어 본 학생 **78%** (75/96) | 이미 다 쓰고 있다 = 시장은 있다 |
| 4 | 이번 학기 강의 녹음 경험 **60%** (58/96) | 입력 데이터를 학생이 이미 갖고 있다 |
| 5 | 시험 기간에 "이게 몇 주차지" 다시 뒤진 시간: 6분 이상 **50%**, 16분 이상 23%(22명), 1시간 이상 7명 | ⚠️ 절반은 0~5분 — **이 숫자는 주장의 중심에 두지 않는다** |

**문제 한 문장**: *"학생 10명 중 8명이 강의를 AI로 요약하지만, 그중 85%는 요약을 못 믿어서 원본을 다시 연다. 요약과 원본 사이에 길이 없기 때문이다."*

⚠️ 정직한 해석: 설문이 지지하는 것은 "시간 낭비"가 아니라 **"요약을 믿을 수 없다 → 원본 확인이 필요하다"**다. 위치 찾기(17%)·뒤진 시간(절반이 5분 이하)은 약하다. 그래서 제품의 중심은 "빨리 찾기"가 아니라 **"모든 문장이 원본으로 가는 길을 갖고 있다(앵커) + 길 없는 문장은 훅이 거부한다"**로 잡는다. 이유 1·2위(문장 확인·원본 이해)는 앵커 클릭 → 그 장면으로 정확히 해결된다.

| 남은 문제 | 지금 학생이 하는 일 |
|---|---|
| 필기가 강의와 따로 논다 | 굿노트 ↔ 녹화본 ↔ PDF를 따로 연다 (설문 문항 없음 — 시연으로 보여 준다) |
| 요약은 쌓이지 않는다 | 강의마다 새 요약 1개, 주차 간 연결 없음 (설문 문항 없음) |

## 2. 사용자와 시나리오

**대상**: 녹화 강의(또는 유튜브 강의)로 복습하는 대학생. 1차 페르소나 = 전공 6과목을 패드로 필기하는 2학년.

**핵심 시나리오 (데모 동선 = 이 순서)**
1. **넣기** — 가진 강의 영상·전사본·슬라이드를 넣는다.
2. **쌓이기** — 에이전트들이 전사본을 구간에 맞추고, 개념 페이지로 컴파일한다. 앵커 없는 문장은 훅이 거부한다.
3. **보기** — 문단 끝 칩을 누르거나 **문장을 드래그 → `원본 보기`** → 그 PPT 슬라이드(또는 프레임) + 영상·녹음의 그 초가 동시에 뜬다.
4. **적기** — 영상이 구간 끝에서 멈춤 → 프레임 옆에 필기 → 저장. 필기에는 코드가 앵커를 붙인다.
5. **자라기** — 강의 1편 → 3편. 페이지·링크 수가 늘고, 같은 개념은 한 페이지로 모인다.
6. **믿기** — 반려 로그(`.history.jsonl`)와 커버리지 N/M으로 "검증이 실제로 돌았다"를 보여준다.

## 3. 왜 에이전트여야 하나 (심사 ②)

- **한 번의 LLM 호출로는 안 된다**: 1시간 전사본(수만 자) → 구간 정렬 → 개념별 승격 → 기존 페이지와 병합 → 검증. 단계마다 읽는 범위·쓰는 권한이 다르다.
- **권한이 다른 7개 역할**: 정렬②은 episodic에 append만, 컴파일③은 concepts/에만, 비평④는 읽기 전용, 사용자👤는 notes/에만. 이걸 프롬프트가 아니라 **코드(훅)로 강제**한다 — AgentGuard(허용 툴 Set) + WritePolicy(쓰기 루트·앵커 존재 확인).
- **모델을 안 믿는 설계**: default deny. 모델은 도구만 부르고, 파일은 훅을 통과한 것만 써진다. 거부되면 이유를 받아 그 문장만 다시 쓴다(자기수정 루프 = 에이전트여야 하는 이유).
- **NotebookLM과의 차이**: 인용은 NotebookLM도 한다. 우리는 ①쌓인다(semantic 페이지 Current/History) ②내 파일이다(마크다운, 옵시디언 호환) ③화면이 점프한다 ④필기가 같은 앵커 체계에 들어온다.

## 3.5 설계 원칙 한 줄 — "코드가 워크플로를 소유하고, 모델은 좁은 판단만 한다" (9/20 추가)

출처: TypeSafe `skills` 레포·Jev 문서 분석(볼트 `sources/2026-09-19__typesafe-skills-jev-analysis`). 원문: *"Code owns the workflow; the model supplies programmable common sense where ordinary code needs semantic understanding."* / *"Typed output guarantees the interface, not truth."*

**Jev API 자체는 쓰지 않는다**: 생성을 안 하는 모델이라 컴파일③에 못 쓰고, 문서가 한국어·CJK 약함을 자인하며, waitlist·레이트리밋이 유동적이다. 대회 당일에 새 의존성을 붙일 이유가 없다. **원칙만 가져온다** — 이미 우리 설계와 같은 방향이라 비용이 거의 없다.

| 그쪽 원칙 | 우리 설계에서 이미/새로 |
|---|---|
| 워크플로·정책은 코드, 모델은 의미 판단만 | 단계 순서·쓰기 루트·재시도 횟수·자동/검토 분기(Merge)·커버리지 N/M 전부 코드 ✅ |
| 타입 있는 좁은 질문, 서로 격리해 병렬로 | 🆕 비평④를 자유 서술 → **문단별 `supported / quote_faithful / from_untrusted` 3문항 JSON**으로. APPROVED·grey 는 코드가 결정 |
| "맞는 게 없음" 선택지를 둔다 | QA `NO_GROUNDING` ✅ · 🆕 구간 경계 판정에 "전환 문장 없음" · 레퍼런스 "못 찾음 → 콜아웃 안 만듦" ✅ |
| confidence 는 행동 허가가 아니다 | 구간표 `confidence<0.55` → 자동 수정이 아니라 **검토함**으로 ✅ |
| 세기·날짜·산수는 코드 | 커버리지·인용 대조 유사도·경계 DP 전부 코드 ✅ |
| 큰 무관한 컨텍스트를 주지 않는다 | QA는 grep 으로 추린 근거 문단만, 비평은 앵커 구간만 ✅ |
| 타입 출력은 인터페이스 보장이지 진실 보장이 아니다 | 그래서 훅(형식) + 비평(내용) + 검토함(사람) 3겹 ✅ |

발표에서 심사 ②("에이전트를 쓸 수밖에 없었나")에 이 한 줄로 답한다: **"모델에게 위키를 맡긴 게 아니라, 코드가 짠 절차 안에서 모델이 '이 말이 이 구간에 있나' 같은 좁은 판단만 합니다."**

## 4.5 화면 — Quartz 위에 얹는다 (9/20 팀장 결정)

**옵시디언은 오픈소스가 아니다**(무료지만 소스 비공개, 수정·재배포 불가). 그래서 "옵시디언 볼트를 웹으로 내는" 오픈소스 **Quartz 5 (MIT)** 를 쓴다. `wiki/` 는 그대로 옵시디언 볼트로도 열린다.

- **Quartz가 그리는 것**: 위키 본문 · 왼쪽 탐색기 · 검색 · 백링크 · 그래프 · 다크 모드. → 우리는 안 만든다.
- **우리가 얹는 것**: 앵커 칩 · 오른쪽 위 **미니 플레이어**(Aside의 PiP처럼 작게) → 누르면 **split**(위 영상·프레임 / 아래 필기) · 맨 오른쪽 **LLM 패널**(입력창 맨 아래 고정, 답변은 위로 쌓임, Gemini식 입력창 = `＋` · 모델 드롭다운 · 전송).
- **얹는 방법**: Quartz 소스를 고치지 않는다. 서버가 모든 HTML의 `</body>` 앞에 우리 JS/CSS 5줄을 **주입**한다. Quartz는 SPA라 초기화는 `nav` 이벤트에 건다.

✅ **9/20 오전 실측**: Quartz 5.0.0, Node ≥22. `npm ci` 10초 · 빌드 5초(이후 0.5초) · `--watch` 있음 → 파이프라인이 `wiki/` 에 쓰면 몇 초 뒤 화면에 뜬다(= "위키가 자란다" 장면). 주입 서버 `tools/devserve.py` 동작 확인.
⚠️ **실측으로 찾은 함정**: Quartz가 우리 앵커 `[[L3#s5@t=330]]` 를 위키링크로 오해해 `<a class="internal">L3 > s5@t=330</a>` 로 그린다 → `viewer.js` 가 이 패턴의 링크를 앵커 칩으로 바꿔치기한다(CONTRACT §7.2). 파일 속 앵커 규약은 안 바뀐다.

## 4.6 위키 파일 형식 = 팀장의 옵시디언 노트 형식 (9/20 결정)

강의 노트(`wiki/lectures/`)는 팀장이 실제로 쓰는 형식 그대로: 주제마다 **📄 슬라이드 → 💡 설명 → 🗣 교수님 말 → 🎯 포인트**.
```markdown
> 🗣 "2의 보수는 1학년 때 배웠을 것. 기억 안 나면 **꼭 구글링해서 계산법을 보라.**" [[L3#s17@t=1820]]
> [!youtube] 보충 영상 (정본 아님)
> - [2의 보수 5분 정리](https://www.youtube.com/watch?v=...) — 교수님 채널
```
- **🗣 인용 = 앵커 필수**(훅이 강제). 누르면 교수가 그 말을 한 녹음·영상의 그 초 + 그 슬라이드. 설문 1위 이유 "시험에 나올 문장·표현 확인 59%"에 정확히 대응한다.
- 교수가 선수 지식을 밖으로 넘긴 곳("찾아보라")에만 ③이 `[!youtube]` 콜아웃을 붙인다. 콜아웃 밖 유튜브 링크는 훅이 거부 → 보충 자료가 정본으로 섞이지 않는다.
- 개념 페이지(`wiki/concepts/`)는 Current/History 유지 — 여러 강의에 걸쳐 "쌓이는" 쪽.
- ✅ 훅 실측 6케이스(정상 allow / 🗣 앵커 없음 / 없는 초 / 콜아웃 밖 유튜브 / 📄 앵커 없음 / 쓰기 루트 밖 → REJECTED). Quartz 렌더 확인(앵커 10개, 콜아웃).

## 4.7 레퍼런스 원문 잇기 (P2 · 9/20 추가)

강의 자료가 논문·교재 기반이면 슬라이드에 인용이 있다("[Vaswani 2017]", "P&H §2.4"). 그 📄 블록 아래 `> [!ref]` 콜아웃으로 **원문 서지 + 링크 + 초록 기반 1~2문장 설명**을 잇는다.
```
슬라이드 텍스트 ─(정규식 + fast 모델)→ 인용 문자열
   → resolve_reference(): arXiv API → Semantic Scholar → Crossref  (무료·키 불필요·EC2에서 됨)
   → 제목 유사도 기준 통과한 것만 raw/refs/<id>.json {title, authors, year, url, abstract}
   → ③ 컴파일이 [!ref] 콜아웃 작성 (초록 밖 내용 금지)
```
- **신뢰 등급 3단**: 강의 원본(앵커 가능) > 레퍼런스·유튜브(콜아웃 안에서만, 앵커 불가) > 제보·필기(untrusted_context).
- **모델이 서지를 지어내는 것이 최대 위험** → 링크·제목·연도는 전부 resolver 결과에서 코드가 채운다. 모델은 설명 문장만. 못 찾으면 콜아웃을 안 만든다.
- 교재 절 인용(P&H §2.4)은 원문을 못 잇는다(저작권) → "교재 §2.4" 표기만.
- 원문 PDF 본문은 가져오지 않는다(초록 + 링크). 저작권·토큰 둘 다.
- ✅ 훅: 외부 링크는 `[!ref]`·`[!youtube]` 콜아웃 밖이면 거부(실측 2케이스).
- 3시간 범위에서는 **P2** — 버리는 순서 맨 앞. 단 포맷과 훅은 지금 들어가 있어서, 데모 강의 1편에 사람이 확인한 `[!ref]` 2~3개를 미리 넣어 "이렇게 이어진다"는 화면은 보여 줄 수 있다.

## 4.8 검토함 (Inbox) — "그래서 내가 뭘 확인하면 되나" (9/20 추가 · P1)

반려 로그는 **시스템이 무엇을 거절했나**(감사 기록)이고, 검토함은 **사람이 지금 확인할 것**(작업 목록)이다. 지금은 확인거리가 `grey`·REJECTED·낮은 신뢰도 구간에 흩어져 있어 사용자 눈에 안 보인다. 대시보드 맨 위에 **"검토 필요 N개"** 하나로 묶는다.

| 검토 사유 | 어디서 나오나 (새 파이프라인 없음 — 전부 이미 있는 데이터) |
|---|---|
| 슬라이드 매칭 불확실 | `segments.json` 의 `confidence` **낮은 순 5개**(확률 아님 — §8.7. 문턱 0.55 는 폐기) |
| 비평 보류 | 페이지 `status: grey` / `draft` |
| 재작성 이력 | `.history.jsonl` 에서 같은 path 가 REJECTED 뒤 allow 된 것 |
| 인용 대조 실패 | 🗣 인용과 그 구간 전사본의 문자 유사도가 낮은 것(§8.5 ④) |

항목마다 **[원본 보기]**(= `anchor-request`, 그 초·그 슬라이드로 점프) **[승인]**. 흐름: 검토 필요 3개 → 원본 확인 → 승인 → 0개. "AI 결과를 그냥 믿지 않는다"는 철학이 화면 한 장으로 보인다 — 설문 85%에 대한 UI 쪽 답.

- **[승인]도 쓰기다 → 훅을 지난다.** WritePolicy 에 규칙 1개 추가: `agent=user` 는 `wiki/concepts|lectures/` 에서 **프론트매터 `status:` 한 줄만** 바꿀 수 있다(본문이 1글자라도 다르면 거부 — 링커의 `links:` 규칙과 같은 방식). 구간 승인은 `segments.json` 의 `confidence` 를 1.0 + `reviewed:true` 로.
- **[수정]은 안 만든다**(3시간 밖). 고치고 싶으면 필기로 남긴다 → 다음 컴파일이 그 구간을 먼저 본다.
- 범위 조정: 대시보드의 "성장 그래프"를 빼고 그 자리에 검토함을 넣는다(일이 늘지 않게). 버리는 순서에서는 유튜브 카드 다음.

## 4.9 Exact Quote Search — 교수님이 실제로 뭐라고 했나 (9/20 추가 · **P1, LLM QA보다 앞**)

일반 검색은 위키 문장(요약)을 찾는다. 이건 **전사본 원문에서 교수의 실제 발언만, 시간순으로** 보여 준다.
```
"시험" 검색 →
  “시험에도 이런 식으로 등장할 가능성이 있고 … A4 용지 써서 쓰면서 연습을 해보길 바래요.” — L1 10:27 · s6 [재생]
```
- 설문 1위 이유 **"시험에 나올 문장·표현 확인 59%"** 에 가장 직접적인 기능. LLM이 없어서 **틀릴 수가 없고**(원문 그대로), 즉시 뜨고, 비용 0.
- ✅ **9/20 실측**(`tools/quote_search.py`, 40줄): 컴퓨터구조 week_2_2 전사본에서 "시험" → 위 문장 1건(s6, 10:27 — 팀장이 손으로 쓴 Ch03 노트의 "⚠️ 시험 신호 ① p6"과 **같은 곳**), "연습" 3건, "중요" 5건. 결과의 `anchor` 로 바로 점프.
- UI: LLM 패널 입력창에 **모드 토글 2개** — `위키에 묻기` | `교수님 발언 검색`. 결과는 카드(인용문 · 강의 · 시각 · 슬라이드 · [재생]). 검색어 추천 칩: 시험 · 중요 · 꼭 · 연습 · 외워.
- 전사가 문단 단위(다글로)면 문단 안 글자 위치로 시각 보간, Grok STT면 문장 시각 그대로.
- 한계: 정확 일치 검색이다. "셤"·오전사는 못 찾는다 → 추천 칩으로 보완.

## 4.10 개념 Merge Preview — 잘못 합치는 것을 막는다 (9/20 추가 · P2)

"여러 강의의 같은 개념을 한 페이지로"가 핵심인데, 모델이 **이름만 같은 다른 개념**을 합치면(자료구조의 Stack ↔ 컴퓨터구조의 Stack 영역) 위키가 조용히 오염된다.
- **재료는 이미 있다**: 훅이 모든 쓰기의 `beforeContent`/`afterContent` 를 `.history.jsonl` 에 남긴다 → 기존 / 새 / 추가될 내용은 그 둘의 diff. 새 저장소·새 에이전트 불필요.
- **자동 vs 검토는 코드가 정한다**(모델이 정하지 않는다): ③이 **기존** 개념 페이지를 고칠 때
  - 기존 `## Current` 문단이 그대로이고 문단·History 줄이 **추가만** 됐다 → 자동 병합.
  - 기존 Current 문단이 **바뀌거나 사라졌다**, 또는 새 강의의 과목(`sources` 의 과목 태그)이 기존과 다르다 → `status: draft` 로 쓰고 **검토함에 `kind:"merge"`** 로 올린다. 카드에 기존 / 추가 / 변경을 3단으로 보여 주고 [승인] / [되돌리기](= history 의 before 로 복원).
- "위키가 자란다"를 숫자가 아니라 **장면**으로 보여 준다: 2번째 강의를 넣자 `bfs` 페이지에 문단 +2, 검토함에 merge 1건.
- 3시간 범위: 검토함(§4.8)이 서면 그 위에 카드 종류 하나를 더하는 일. 강의 2편 이상 컴파일이 전제라 **P2** — 버리는 순서에서 Grok STT 라이브 다음.

## 5. 유튜브 = 보충 추천 (입력 경로 아님 — 9/20 팀장 결정)

LLM 패널은 **위키에만 근거해** 답한다. 그 답변 **아래**에 "관련 영상" 카드 2~3개가 붙는다. **교수님 채널 검색 결과가 먼저**, 그다음 일반 검색. 위키에 근거가 없을 때는 "위키에 근거 없음" + 영상 카드만 나온다 — 모르는 걸 지어내는 대신 볼 곳을 알려 준다.

- 영상은 **앵커가 될 수 없고**, 위키에는 `[!youtube]` 콜아웃으로만 들어간다(§4.6)(signals·notes와 같은 비정본 취급). 정본은 여전히 강의 원본뿐.
- ✅ 저장소 확인: `ZeroPointRepo/youtube-skills`(⭐886, 9/15 푸시) = **TranscriptAPI.com SaaS 래퍼**, 무료 100크레딧 → **HTTP를 `api/` 에서 직접 호출**. `alexmercerind/youtube-search-python` = **2022-06 이후 방치·아카이브 → 안 쓴다.** yt-dlp = README가 "YouTube blocks all major cloud IPs" 명시 → **EC2에서 못 쓴다.**
- 크레딧 방어: 모든 검색 응답을 `raw/.ytcache/` 에 캐시, 발표 질문 3개는 미리 데워 둔다. 실패하면 카드만 빠지고 답변은 나온다.
- API: `GET /api/youtube/search?q=` · `/api/qa` 응답의 `videos[]` (CONTRACT §5.1).

## 8.5 아직 구멍인 곳 (9/20 자체 검토 — 중요도 순)

**① 녹음 + PDF만 있는 강의는 구간표(`segments.json`)를 만들 방법이 아직 없다. ← 가장 큰 구멍**
지금 구간표는 mp4 장면 분할에서만 나온다. 녹음에는 장면이 없다 → 구간표 없음 → `source_exists` 가 전부 거부 → 위키가 한 줄도 안 써진다. 팀장의 실제 데이터(다글로 전사본 + 강의 PDF)가 바로 이 경우다.

풀어야 할 문제: **"교수가 몇 초에 몇 번 슬라이드로 넘어갔나"를 녹음만 듣고 알아내기.** 입력은 슬라이드 N장의 텍스트와 타임스탬프 달린 전사 문장 M개, 출력은 N개의 경계 시각.

1. **재료 만들기(코드)**: PDF → 슬라이드별 텍스트(`pdftotext -f k -l k`) + PNG(`pdftoppm`). 전사본 → `transcript.json [{t_start,t_end,text}]`. 전사본을 30초 창으로 묶는다(창 W개).
2. **점수표(코드)**: 슬라이드 i × 창 j 마다 "슬라이드 i의 고유 단어가 창 j에 몇 번 나오나". 고유 단어 = 그 슬라이드에는 있고 다른 슬라이드엔 드문 단어(TF-IDF). 영어 용어·숫자·기호(`addi`, `O(V+E)`)가 한국어 강의에서 특히 잘 잡힌다 — 교수는 슬라이드의 영어 단어를 그대로 읽는다.
3. **단조 제약으로 경계 찾기(코드, 동적계획법)**: 슬라이드는 1→2→3 순서로만 넘어간다고 가정하고, W개 창을 N개 연속 덩어리로 자르는 모든 방법 중 점수 합이 최대인 것. N=20·W=120이면 계산은 순식간이다. 이 제약이 핵심이다 — 없으면 같은 단어가 나오는 앞뒤 슬라이드로 마구 튄다.
4. **애매한 경계만 모델에게(fast)**: 경계 앞뒤 점수 차가 작은 곳만 골라 "이 1분 전사본에서 교수가 다음 슬라이드로 넘어간 문장은?"을 묻는다. 단서 표현("다음 장", "넘어가서", "여기 보시면")이 있으면 그 문장의 `t_start` 가 경계. 강의당 5~10번 호출.
5. **훅**: `frame_guard.py` — 구간 겹침·역전·빈 구간이 있으면 거부. 통과 못 하면 그 강의는 ② 정렬로 못 넘어간다.
6. **사람 검수 5분**: 경계 목록(슬라이드 썸네일 + 그 초의 전사 한 줄)을 보고 틀린 것만 고친다.

안 되는 경우(정직하게): 교수가 슬라이드를 **되돌아가는** 강의(단조 가정 위반 → 그 구간은 앞 슬라이드에 붙는다) · 그림만 있는 슬라이드(텍스트 0 → 앞뒤 경계 사이를 균등 분할) · 슬라이드 없이 길게 말하는 구간(가장 가까운 슬라이드에 붙고 `kind:"talk"`). 셋 다 점프는 되지만 슬라이드가 어긋날 수 있다 → 검수에서 잡는다.

- ✅ **9/20 오전 실측 — `tools/align_slides.py` (모델 호출 0회, 1초 미만)**: 컴퓨터구조 week_2_2(슬라이드 21장 = lecture-md 교본의 `<!-- page N -->`, 다글로 전사 58문단·54분) → 구간 15개, 겹침·역전·빈틈 0. 전사본의 "다음 슬라이드로 넘어가서"와 대조한 s7→s8(15:3x)·s8→s9(30:31)·s9→s10(33:28) 경계가 일치. 말 없이 지나간 슬라이드 6장(표지·같은 요약표 2장·표 슬라이드)은 구간 없음.
  - 슬라이드 재료는 **lecture-md 스킬 교본을 그대로 쓴다**(표 OCR까지 돼 있어 pdftotext보다 낫다). 1~2단계가 이걸로 끝난다.
  - ✅ Grok STT는 단어 단위 시각을 준다 → 경계를 문장 단위(±수 초)로 잡을 수 있다. `align_slides.py` 는 `transcript.json` 도 입력으로 받는다. **정밀도가 필요한 데모 강의는 Grok STT로 다시 전사하는 쪽이 낫다.**
  - 다글로 md는 문단(약 50초) 단위 타임스탬프뿐 → 경계 오차 최대 ±50초. 단서 표현 위치로 문단 안을 글자 비례 보간해 줄였다(7~8개 경계). 문장 단위 타임스탬프(Grok STT·다글로 원본 JSON)가 있으면 더 좋아진다.
  - 잡은 오탐: "다음 슬라이드**에서** 설명할 겁니다"(예고)를 전환으로 오인 → "다음 슬라이드**로**"만 단서로. 4단계(모델 판정)는 `confidence<0.55` 구간에만 쓰면 된다 — 이 강의는 1곳.
  - 정답지가 없어 정확도 수치는 아직 없다. 검수 5분은 그대로 필요.
- 데모 강의는 시작 전에 이 도구로 구간표를 만들어 둔다. 발표에서는 "자동 초안 + 5분 검수"라고 그대로 말한다.
- 이것이 이 제품의 핵심 난제이고 심사 ②의 가장 정직한 답이다: 규칙만으로는 애매한 경계가 안 잡히고, 모델만으로는 초가 틀린다 → **코드 제약(단조) + 모델 판정(애매한 곳만) + 훅 검증 + 사람 검수.**

**② 교수님 강의 자료를 public 저장소에 올리면 안 된다.**
녹음·전사본·PPT는 교수님 저작물이다. 저장소가 public이면(EC2 git pull 편의) 그대로 공개된다. 설문 xlsx에도 소속 등 개인정보가 있다.
- 실제 `raw/` `wiki/` 데이터와 설문 원본은 **커밋하지 않는다**(gitignore). EC2에는 `scp`/`rsync` 로 올린다. 저장소에는 지금의 가짜 견본(L3 그래프 탐색)만 둔다.
- OpenAI 무료 티어는 입력이 학습에 쓰일 수 있는 조건 → 교수님 전사본 컴파일은 Anthropic/Gemini 유료 키 쪽으로. 무료 티어는 견본 데이터·QA fast 용.
- 발표에서 교수님 음성을 트는 범위도 짧게. 가능하면 교수 공식 공개 영상(유튜브)으로 시연.

**③ 3시간에 비해 범위가 커졌다 — 버리는 순서를 미리 정한다.**
오전에만 Quartz·LLM 패널·유튜브·STT·드래그·새 노트 포맷이 붙었다. 시간 모자라면 **아래부터** 버린다:
레퍼런스 [!ref] 자동 → Grok STT 라이브 → Merge Preview → 유튜브 카드 → 검토함 → 커버리지 N/M → ④ 비평 → split(미니 플레이어만) → LLM 패널.
**끝까지 지키는 것 4개**: (0) 교수님 발언 검색(이미 동작, 40줄) (a) 노트에서 🗣·📄 클릭 → 그 초·그 슬라이드 (b) 훅 거부 사유가 화면에 뜨는 장면 (c) 설문 85%.
- 1:30 통합 점검에서 (a)가 안 되면 그 시점에 아래 4개를 즉시 버린다.

**④ "에이전트가 실제로 돌았다"는 증거가 로그뿐이다.**
미리 컴파일한 결과만 보여 주면 "그냥 요약 앱"으로 보인다. 발표 중 **라이브로 1주제만 컴파일**해서 REJECTED → 사유 받고 그 문장만 다시 씀 → allow 가 대시보드에 한 줄씩 올라오는 장면을 넣는다(30초).
- 값싼 숫자 하나 더: **"🗣 인용 N개 중 전사본 대조 통과 M개"** — 인용문과 그 앵커 구간의 전사본을 문자 유사도로 비교(코드 20줄, LLM 불필요). 지어낸 교수님 말을 잡는다. "요약을 못 믿는다 52%"에 대한 직접 답.

**⑤ 발표 자료 담당이 없다.**
레인 4개가 전부 코드다. 7분 발표·설문 장표·백업 영상은 아무 레인에도 없다. → 2:00부터 한 명(권장: 민수, T5를 비움)이 장표 5장 + **데모 녹화 백업**(현장 와이파이·EC2가 죽어도 발표는 한다). 장표: 문제(85%) → 데모 → 왜 에이전트(쓰기 루트 표·훅 10개) → 구멍과 다음 → 팀.

**⑥ 작지만 적어 둘 것**
- 로그인 없음 = 필기는 전원 공유. 데모 전용이라고 명시(비목표).
- Quartz가 `wiki/notes/` 를 빌드에서 뺀다(설정 완료) — 필기는 API로만 보인다.
- 한 강의 컴파일 비용 감: 1시간 전사 ≈ 2~3만 토큰 입력 × 주제 수. strong 모델로 강의당 수백 원대 추정(⚠️ 미측정) → T3에 1편 돌리고 실측해 장표에 넣는다.

## 8.7 confidence 3종 — 무엇을, 어떻게 재고, 어떻게 쓰나 (9/20 실측 모음)

| 무엇의 confidence | 어떻게 얻나 | 실측 | 쓰임 |
|---|---|---|---|
| **A. 슬라이드 경계**(이 초가 이 슬라이드가 맞나) | 점수 비(자기 ÷ 자기+경쟁) — 아래 §8.7-A | 오차를 설명 못 함(0.56→12초, 0.80→54초). **미검증** | 확률 아님. 강의당 낮은 순 5개를 검토함에 |
| **B. 모델 판단**(이 문단이 이 구간에 근거가 있나) — Jev식 | 선택지 분포의 쏠림: 모델 간 불일치 → 표본 빈도 → (되면) logprobs — §8.8 | 애매한 주장에서만 분포가 갈림(12/12 vs 9:3). xAI는 logprobs 안 줌 | 갈리면 검토함. 자동 승인 없음 |
| **C. 음성 인식**(이 문장을 제대로 받아 적었나) | **두 전사본의 일치율**(다글로 × Grok) — §8.9 | 10문장 중 9개 92~100%, **1개 63% = 실제 오인식 지점** | 50% 미만 경고 · 80% 미만 표시 — §8.9 |

셋 다 **보정 전에는 확률이 아니다.** 보정 데이터는 검토함의 승인/되돌리기 기록에서 나온다(§8.8).

### 8.7-A 슬라이드 경계 confidence — 지금은 못 잰다, 그래서 이렇게 쓴다

**현재 값의 정체**: `align_slides.py` 의 `confidence` = 그 구간에서 (자기 슬라이드 점수) ÷ (자기 + 가장 센 경쟁 슬라이드 점수). 확률이 아니고, 0.55 라는 문턱도 근거 없는 임시값이다.

✅ **실측(week_2_2)**: 교수가 "다음 슬라이드로 넘어가서"라고 말한 시각을 정답 대용으로 삼아 DP 경계와 비교.
- 단서가 근처에 있는 경계 7개: 오차 0·3·12·16·29·32·54초(중앙값 16초, 문단 단위 전사라 최대 ±50초가 한계).
- **그런데 confidence 는 오차를 설명하지 못했다**: conf 0.56 → 12초, conf 0.80 → 54초. 새로 시험한 지표(경계를 한 문단 옮길 때 점수 낙폭)도 마찬가지. 나머지 7개 경계는 교수가 단서 없이 넘어가 **정답 자체가 없다.**
- 결론: **표본 7개로는 어떤 지표도 검증되지 않는다.** "신뢰도 0.8" 같은 숫자를 화면이나 발표에 확률처럼 내놓으면 안 된다.

**그래서**
1. **이름과 쓰임을 낮춘다**: 확률이 아니라 **검수 순서**. 화면에는 숫자 대신 "⚠ 먼저 확인" 배지. 문턱은 확률이 아니라 **예산**으로 — "강의당 가장 낮은 5개를 검토함에".
2. **정답을 만든다(강의당 10분)**: `align_slides.py --review` 출력(슬라이드 · 추정 시각 · 그 초의 전사 한 줄)을 사람이 고친 것이 곧 정답표. 검수 작업이 그대로 평가 데이터가 된다 → 강의 3편이면 경계 60개.
3. **그때 재는 것**: ① 경계 오차 중앙값, 10초·30초 안에 든 비율 ② **초 단위 정확도** = 전체 재생 시간 중 올바른 슬라이드에 배정된 비율(사용자가 체감하는 값) ③ **검수 효율** = 점수 낮은 순으로 k개를 봤을 때 실제 오류(30초 초과)의 몇 %를 잡나. 후보 지표(점수 비·낙폭·단서 유무·슬라이드 고유 단어 수·Grok 단어 시각 유무)를 ③으로 비교해 하나를 고른다.
4. **모델 판단에는 숫자 신뢰도를 묻지 않는다**: LLM이 스스로 매긴 0~1 은 보정되지 않는다. 비평④는 `yes/partial/no` 범주만 받고, 불확실성은 **불일치로** 잰다 — 같은 질문을 다른 모델(fast ↔ gemini) 또는 2회 물어 답이 갈리면 검토함. 🗣 인용 충실도는 모델이 아니라 **문자 유사도(코드)**.
5. 발표에서는 그대로 말한다: "자동 초안의 경계 오차 중앙값 16초(단서 있는 7곳 기준), 신뢰도 지표는 아직 검증 전이라 검수 순서로만 씁니다."

## 8.8 Jev식 confidence(선택지 분포의 쏠림)를 Jev 없이 얻는 법 (9/20 실측)

Jev의 confidence = **선택지 위 확률 분포가 얼마나 한쪽으로 쏠렸나**(Choice·Score). 개별 답의 정답 보증이 아니라 "0.8 붙은 것들이 집단으로 약 80% 맞는다"는 **보정**이 핵심이고, 문서도 *"confidence … not permission to act"* 라고 못박는다. 일반 LLM으로 같은 모양을 만드는 길은 셋.

| 방법 | 어떻게 | 실측·가용성 |
|---|---|---|
| ① 토큰 확률(logprobs) | 답을 한 글자(A/B/C)로 강제 → 첫 토큰의 `top_logprobs` 를 선택지끼리 softmax → 분포. confidence = 1 − 정규화 엔트로피. TypeSafe `system-one-adapter-python` 의 `llm_answer_mode="probabilities"` 가 이 방식 | ✅ **xAI(grok-4.20 non-reasoning · grok-4.3): `logprobs:true` 를 보내도 안 돌려준다.** Anthropic API 는 logprobs 없음. OpenAI 비추론 모델(gpt-4.1-mini 등)·Gemini 일부는 지원 — ❓ 키 넣고 확인 필요. 추론 모델(o4-mini)은 불가 |
| ② 표본 빈도 | temperature 1 로 같은 질문 N회 → 답의 빈도가 분포 | ✅ grok-4.20, 12회 병렬: 명백한 주장 `A 12/12`(1.00) · 애매한 주장(근거가 절반만 있음) `A 9 · B 3`(0.75). 3문항×12회 = 16초. **쏠림이 실제로 애매함을 따라간다** |
| ③ 모델 간 불일치 | 같은 질문을 서로 다른 모델에 1회씩 | ✅ 같은 애매한 주장에 grok-4.20 = A, grok-4.3 = B 로 갈림. 가장 싸다(2콜) |

**채택**: 비평④의 문단별 판정은 **③(2모델 1회씩) → 갈리면 ②(8회 표본)**. logprobs 되는 공급자가 확인되면 ①로 교체(1콜에 분포가 나와 제일 싸다). 분포·표본 수는 `.history.jsonl` 에 같이 남긴다.

**이 숫자도 검증 전에는 확률이 아니다.** 보정은 정답표가 있어야 잰다:
- 정답표 = **검토함의 승인/되돌리기 기록**. 사람이 누를 때마다 (모델 분포, 사람 판정) 한 쌍이 쌓인다 → 새 작업 없이 보정 데이터가 생긴다.
- 재는 법 = 신뢰도 구간표: 쏠림 0.9~1.0 / 0.7~0.9 / ~0.7 로 묶어 구간별 실제 정답률. 0.9 구간이 90% 근처면 보정된 것. 50쌍은 있어야 의미가 있다 → 해커톤 범위 밖, "다음 단계".
- Jev 문서가 자인한 함정도 같이 가져온다: **같은 것을 두 방식으로 묻지 않는다**(yes/no 와 3지선다를 섞으면 확률이 서로 안 맞는다 — 그쪽 실례: 0.22 vs 0.01), 선택지에 **"근거 없음"을 항상 둔다**, 쏠림이 높아도 자동 승인하지 않고 **정책은 코드**(no 하나라도 → 보류).

## 8.9 Grok STT 예시본 + 음성 confidence (9/20 실측)

**요청** `POST https://api.x.ai/v1/stt` · multipart `file=@clip.mp3`, `language=ko` · 헤더 `Authorization: Bearer $X_AI`
**입력** 컴퓨터구조 week_2_2 녹음의 15:00~16:00 (60초, mono 16kHz mp3 360KB) → **응답 2.9초**

```json
{"text": "그래서 우리 컴퓨터 발전에 거의 …", "language": "ko", "duration": 60.048,
 "words": [{"text": "그래서", "start": 0.44, "end": 0.72}, {"text": "우리", "start": 0.82, "end": 0.96}, {"text": "컴퓨터", "start": 1.12, "end": 1.521}, {"text": "발전에", "start": 1.581, "end": 2.081}, {"text": "거의", "start": 2.801, "end": 3.121}, {"text": "어", "start": 3.521, "end": 3.561}, … 총 121개]}
```
단어마다 `start`/`end`(초). **단어별 confidence 필드는 없다**(키는 `text,start,end` 뿐).

`tools/stt_grok.py` 가 문장부호에서 끊어 만든 `transcript.json`(발췌, 수업 자료라 짧게만 싣는다):

| 시각 | Grok STT 문장 | 다글로와 일치 |
|---|---|---|
| 15:12.5 | 그래서 우리 삼성이 정말 잘해주는 게 메모리잖아요. | 100% |
| 15:23.6 | 그래서 **스몰 리스트 파스터**, 그래서 우리는 레지스터 이렇게 갖고 와서 쓴다. | **63%** |
| 15:27.6 | 요거를 소개해 주고 싶었고, 자, 다음 슬라이드로 넘어가서, 다음 슬라이드로 넘어왔어. | 94% |
| 15:34.6 | 어서, 자, 이제 레지스터를 하나씩 소개를 해 줄까 합니다. | 95% |
| 15:51.3 | 32개의 레지스터 파일이 있다. | 100% |

**음성 confidence = 두 전사본의 일치율.** STT가 자기 신뢰도를 안 주므로, 서로 다른 엔진 둘(다글로 × Grok)이 같은 구간을 어떻게 받아 적었는지 글자 단위로 맞춰 본다(코드, 공백·문장부호 제거 후 공통 부분 비율).
- ✅ 10문장 중 9개가 92~100%, **63% 하나가 정확히 오인식 지점**이었다: 슬라이드 p7의 *"Smaller is faster"*(Design Principle 2)를 Grok은 "스몰 리스트 파스터"(다른 실행에선 "smallest faster"), 다글로도 다르게 받아 적음. **두 엔진이 갈리는 곳 = 둘 다 못 믿을 곳.**
- 엔진이 하나뿐이면: 같은 엔진으로 두 번 돌려 비교(위처럼 Grok은 실행마다 이 구절이 달라졌다) — 약하지만 공짜에 가깝다.

**사용자에게 알리는 방식 (팀장 제안: 50% 미만이면 알림 → 채택, 단계 하나 추가)**
| 일치율 | 화면 | 파이프라인 규칙(코드) |
|---|---|---|
| **50% 미만** | 🔈 **"음성 인식이 불확실합니다 — 원본을 들어 보세요"** 경고 + [재생] · 검토함 `kind:"stt_uncertain"` | 그 문장은 **🗣 인용으로 쓸 수 없다**(훅 거부). 발언 검색 결과에도 경고 표시 |
| 50~80% | 문장에 점선 밑줄 + 🔈 작은 표시(누르면 그 초 재생) | 🗣 인용 가능하되 비평④가 우선 확인 |
| 80% 이상 | 표시 없음 | — |

- 50% 하나만 쓰면 **이번 실측의 실제 오인식(63%)을 놓친다** → 80% 표시 단계를 같이 둔다. 두 문턱 모두 표본 10문장짜리 임시값이고, 검수 기록이 쌓이면 다시 잡는다(§8.7 원칙 그대로).
- 덤: 일치율이 낮은 구간에 **그 슬라이드의 영어 용어**가 있으면 교정 후보로 띄운다("Smaller is faster"). 교수는 슬라이드 단어를 읽는다 → 슬라이드가 곧 용어 사전. P2.
- `transcript.json` 에 선택 필드 `agree`(0~1) 추가. 없으면 "측정 안 됨"이지 "확실함"이 아니다.
- 비용: 전사를 두 번 한다. 다글로는 이미 있으니 추가는 Grok 1회(❓ 요금 미확인).
